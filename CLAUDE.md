# Inertia

- Inertia creates fully client-side rendered SPAs without modern SPA complexity, leveraging existing server-side patterns.
- Components live in `resources/js/pages` (unless specified in `vite.config.js`). Use `Inertia::render()` for server-side routing instead of Blade views.

# Inertia v3

- Use all Inertia features from v1, v2, and v3. Check the documentation before making changes to ensure the correct approach.
- New v3 features: standalone HTTP requests (`useHttp` hook), optimistic updates with automatic rollback, layout props (`useLayoutProps` hook), instant visits, simplified SSR via `@inertiajs/vite` plugin, custom exception handling for error pages.
- Carried over from v2: deferred props, infinite scroll, merging props, polling, prefetching, once props, flash data.
- When using deferred props, add an empty state with a pulsing or animated skeleton.
- Axios has been removed. Use the built-in XHR client with interceptors, or install Axios separately if needed.
- `Inertia::lazy()` / `LazyProp` has been removed. Use `Inertia::optional()` instead.
- Prop types (`Inertia::optional()`, `Inertia::defer()`, `Inertia::merge()`) work inside nested arrays with dot-notation paths.
- SSR works automatically in Vite dev mode with `@inertiajs/vite` - no separate Node.js server needed during development.
- Event renames: `invalid` is now `httpException`, `exception` is now `networkError`.
- `router.cancel()` replaced by `router.cancelAll()`.
- The `future` configuration namespace has been removed - all v2 future options are now always enabled.

# Project guide

## What this repository is

An unmodified `laravel/svelte-starter-kit` (Laravel 13 · PHP 8.5 · Svelte 5 · Inertia 3 · Fortify · Wayfinder · Tailwind 4) that is being turned into **Faturly**, AT-certifiable Portuguese invoicing software, reimplemented from an existing Go v3 codebase. Only the starter-kit auth/settings surface exists today; no fiscal domain code has been written yet.

Two documents govern the work and outrank anything you infer from the code:

- **`SETUP.md`** — the stack setup plan (Bun, local Postgres + RLS, Sanctum API surface, Scramble). Six numbered steps with a dependency order at the bottom and a `**Verify**` block per step. **None of it is executed yet.**
- **`PORTING.md`** — the language-agnostic build spec for the fiscal domain (~1300 lines). Every rule carries a tier: **[A]** compliance contract (law/inspector doctrine — byte-exact, failure = certification failure), **[B]** architectural guarantee (reproduce the guarantee, mechanism may be idiomatic), **[C]** Go-codebase implementation choice (free to change). Where the doc and `saftpt1.04_01.xsd` disagree, the XSD wins.

Before writing any fiscal code, read the relevant `PORTING.md` section. Do not derive fiscal behavior from first principles — the dominant failure mode is byte divergence, not logic error.

## Architecture

**Auth is Fortify's, not this app's.** No login/register/2FA/passkey routes exist in `routes/`; Fortify registers them. `FortifyServiceProvider` is the whole wiring surface — it maps each Fortify view to an `Inertia::render('auth/…')`, points `createUsersUsing`/`resetUserPasswordsUsing` at `app/Actions/Fortify/`, and defines the `login` / `two-factor` / `passkeys` rate limiters. To change an auth screen, edit the provider and the Svelte page, not the routes.

**Validation rules are shared traits, not per-request arrays.** `app/Concerns/ProfileValidationRules.php` and `PasswordValidationRules.php` are consumed by both `app/Http/Requests/Settings/*` and the Fortify actions, so one rule change covers the web form and the Fortify path. Add rules there rather than inlining them in a FormRequest.

**Layouts are resolved by page-path convention** in `resources/js/app.ts`, not per page: `Welcome` → no layout, `auth/*` → `AuthLayout`, `settings/*` → `[AppLayout, SettingsLayout]`, everything else → `AppLayout`. A new page slots into a layout by where you put its file.

**Flash messages are Inertia flash + a toast listener.** Controllers call `Inertia::flash('toast', ['type' => …, 'message' => …])`; `resources/js/lib/flash-toast.ts` (initialized once in `app.ts`) renders it via `svelte-sonner`. Don't hand-roll session-flash reads in pages.

**Shared props** come from `HandleInertiaRequests::share()`: `name`, `auth.user`, `sidebarOpen`. The `appearance` and `sidebar_state` cookies are deliberately excluded from encryption in `bootstrap/app.php` so `HandleAppearance` and the client can both read them.

**`AppServiceProvider::configureDefaults()`** sets app-wide invariants: `CarbonImmutable` as the date class, destructive DB commands prohibited in production, and strict `Password::defaults()` in production only (null elsewhere, so tests and local dev accept weak passwords).

## Generated code — never edit by hand

`resources/js/actions/`, `resources/js/routes/`, and `resources/js/wayfinder/` are Wayfinder output, regenerated by the Vite plugin (and `php artisan wayfinder:generate`). Change the PHP route or controller, then re-run. Import typed route helpers from `@/actions/…` and `@/routes/…` instead of writing URL strings.

## Fiscal invariants (apply the moment domain code starts)

These are settled decisions from `SETUP.md` §6 and `PORTING.md`; they are expensive to retrofit and must not be "modernized":

- **No floats for money, ever.** No `float` casts, no `round()`, no `number_format()` on monetary values. Use `Brick\Math\BigDecimal` (ships with Laravel 13) behind a single `Dec` value object. Columns are `decimal(19, 6)` → Postgres `NUMERIC`, cast with `decimal:6`.
- **One value, one rendering.** Any value that gets signed, QR-encoded, printed and SAF-T-exported also stores its rendered bytes in a sibling `text` column; the signature reads that column and never re-formats the numeric.
- **Signing is RSA-SHA1 / PKCS#1 v1.5 / 1024-bit** — `openssl_sign($msg, $sig, $key, OPENSSL_ALGO_SHA1)`. Not sodium, not SHA-256, not PSS.
- **SAF-T is Windows-1252**, not UTF-8; build as UTF-8, then `mb_convert_encoding(...)` and match the XML declaration.
- **Emission serializes on `SELECT pg_advisory_xact_lock(hashtext(:seriesKey))`** as the first statement of the emission transaction.
